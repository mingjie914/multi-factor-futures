# 因子检验与准入流程

本文是因子有效性准入的唯一语义说明。阈值以
`config/default.yaml::validation_policy`为准，IDE唯一入口为项目根目录
`run_factor_workflow.py`。

## 唯一流程拓扑

```text
注册因子池
  -> 正式统计准入
  -> 有效因子库
  -> 相关聚类/子集选择
  -> 具体策略
  -> 组合级 Walk-forward / locked OOS / 前向观察
  -> 人工生产批准
```

三个概念不得混用：

- 因子有效：该因子通过正式统计准入，与其他因子无关。
- 因子冗余：两个有效因子在某个冻结样本和策略语境下高度相关。
- 组合有效：一个确定因子集合在固定组合方法下通过组合级样本外验证。

相关簇和组合结果不得删除、降级或反写有效因子身份。

## 正式统计准入（默认）

正式运行使用从`date_policy.factor_admission_start`到含端点
`date_policy.research_cutoff`的冻结历史区间。因子计算额外读取
`validation_policy.warmup_days_by_frequency.daily`日历日预热。截止日后的数据不得参与
因子发现、周期选择或准入。`date_range.start`仅是普通回测/观察起点，不改变正式准入样本。

普通回测默认遵循 `config/default.yaml::date_range`：起点取配置值，终点
`latest_available` 解析为所选数据源的最新完整交易日。组合对比入口默认继承该起点，
也允许显式指定本次对比起点；所有参与组合统一区间，额外预热不计入净值区间。
组合搜索与生产回测的 `cap3` 均使用 `core.sectors.portfolio_selection_group_for`
给出的五大选池分组，不能以细分行业分类替代；具体映射写入搜索合同。
含端点的研究截止日单独标注，其后的交易日称为“模拟实盘观察期”，只观察冻结的
因子成员、方向和组合方法，不据此重新选择；该名称不等同于真实成交或未被查看过的样本外。

多数分钟输入因子声明`validation_horizons=(5,10,20)`，日线量价相关性五因子声明
`(10,20,40)`；正式任务读取各类实际声明并冻结，不按所在文件名统一覆盖。
这些是未来交易日收益预测期，不表示再做相同天数平滑，也不自动建立策略袖套；
输入bar、日频输出和预测期分别校验。新增因子须有明确声明及相应测试。

默认甜区合同版本为`factor_admission_ic_hac_v1`：统计量固定为逐日截面IC序列的
Newey-West/HAC均值检验，暴露预处理固定为逐日MAD去极值和截面z-score。日期、门槛、
假设族、代码、配置和数据指纹均写入`run_contract.json`；任一变化必须建立新run，不能
续跑或覆盖既有证据。

正式门槛依次为：

1. 每个因子的局部p值以Simes聚合，全部因子执行BH，`q=0.10`。
2. 第一层选中的因子内部执行selection-adjusted local BH。
3. `|IC| >= 0.01`、`|IC/HAC t| >= 2.0`。
4. 已预声明方向时不得与其冲突。
5. 通过现有稳健性、样本充分性和适用的成本覆盖后置门。

Bonferroni/FWER、ICIR、命中率、月换手、分层单调性和记分卡保留为诊断，不是默认
准入硬门。相关性、126/42单切分、滚动Walk-forward和locked OOS也不是单因子准入门。

注意“月换手不是硬门”不代表“当前完全不考虑换手”：既有成本覆盖后置门使用换手
代理估算成本。用户提出将交易经济性移至组合层的建议尚未落实为准入合同变更；
本轮通用成本审阅没有修改上述门槛、既有通过名单或有效库。现状、局限及待决事项见
[交易成本与换手口径](交易成本与换手口径.md)，不要将建议方案当作当前准入规则。

正式run固定输出：

- `factor_validation_full.csv`：全部送检因子及逐门判断；
- `passed_factors.csv`：全部正式通过者；
- `validation_summary.json`：范围、窗口、通过数量和唯一准入语义；
- `artifacts/ic_by_window_period.json`与`validation_funnel.json`：完整统计证据；
- `artifacts/performance.json`：分批/阶段墙钟耗时、日期分块及逐因子热点，纯诊断；
- `run_contract.json`：因子名单、范围、政策与文件哈希。

只有`run_contract.json`同时声明
`workflow=factor-admission-validation`和`admission_eligible=true`的run可以入库。

## 送检范围

同一统计实现支持两种范围，运行时必须二选一：

- `VALIDATE_FACTOR_BATCH`（默认）：送检一次预先冻结的新增批次；必须填写非空
  `FACTOR_NAMES`。不得因结果不理想事后拆分批次重跑。
- `VALIDATE_ALL_INTRADAY`：第一次建库或正式重建时，显式送检全部注册日内因子。

两种范围都把本次送检因子及其所有注册周期视为本次多重检验族。程序拒绝同时指定或
同时遗漏两个范围。

两类run的入库语义也不同：新增批次只合并本次通过者；全池重建以本次通过者完整替换当前
有效库，防止未通过重检的旧成员被静默保留。

## 入库

正式检验只生成不可变证据，不自动改变库。人工检查完成后，单独选择
`ADMIT_COMPLETED_RUN`，填写`ADMISSION_RUN_DIR`和`ADMITTED_AT`。

有效库保存所有统计通过者，不进行相关性去重。每条记录仅保存：名称、稳定的
`family/category`、`input_bar_frequency`、`signal_frequency`、单一`best_period`证据标签、
方向、IC/t/q、研究窗口及证据哈希。完整`validation_horizons`只保留在研究合同和产物中。
`best_period`不限制组合调仓或持仓周期。

方向按准入样本IC符号冻结；已有预声明方向时拒绝相反结果，未预声明时保留为探索性方向。
组合先反转负向因子的日截面排名，再共同合成，不用后续评价段重新择优翻转方向。
分层单调性目前仅作诊断：实际指标为组号与各组年化收益的Pearson相关系数，
不是严格逐组递增检验；应结合冻结方向解释。2026-07-26版本曾有绝对值0.5硬门，
2026-07-28提交e86fc89已取消，2026-09-07的119库及此次数据修补重检均未使用该硬门。

## 相关簇与策略选择

相关聚类属于`workflows/factor_selection.py`。它只读取当前有效库，并把最小标识写入本次
选择产物：`cluster_id`、相关度量、算法、阈值和冻结样本合同。`cluster_id`只在该run内有
意义，不写入有效库作为永久属性。

从零建立组合时，准入与组合选择分别冻结日期。正式准入仍使用上述近期窗口；
组合选择默认使用2016-03-31至研究截止日，并额外读取预热，完整配方仍由配置给出。

1. 读取当前有效库全部成员及冻结方向；聚类只输出冗余诊断，不永久剔除非代表成员。
2. 全部日频暴露按配置的ICIR、Top/Bottom、cap、ERC及成本共同合成。
3. 从多个二因子组合起步，以宽度20保留多条向前搜索路径；每个规模选至多3条
   成员不同的提案做精确组合回测。下一规模优先保留上一规模精确最优者的一条扩展，
   其余位置仍由多路径提案竞争，不锁死为一条嵌套路径。
4. 完整探索2至20个因子；20仅为计算预算，任何连续未改善均不触发早停。
   提案由分段IC生成，因此这是有限搜索，不是全局穷举或全局最优证明。
5. 按2016-2019、2020-2021、2022-2023、2024、2025至截止日五个历史块记录
   净收益稳健性；至少四个有效块、60%正Sharpe块、正中位Sharpe和正全期年化
   才进入候选比较。这些是组合候选筛选条件，不影响单因子准入。
6. 按盈利段比例、最差/中位Sharpe、收益、回撤、换手的非支配前沿保留至多5个
   成员Jaccard低于0.85的候选。不按因子数量加分，不凑足候选数量。
7. 输出 portfolio_candidates、size_candidates 和全部精确评价。
   recommended_core仅是便于兼容展示的首项，不是唯一候选或生产批准。
   净值图复用组合流程的中文对比绘图函数，输出`nav_comparison.png`，标注实际区间及历史开发样本性质。

历史区间是参与选择的开发样本，且候选库及方向来自近期准入，因此它不是独立
样本外，也不是历史当时可获得因子名单的逐折仿真。需要独立逐折评估时，必须在
每个训练窗口内重做候选选择，冻结到后续测试窗口；不能将这里五段重新命名为OOS。
截止日后行情不参与本流程，组合生产批准仍由后续模块显式完成。

2026-09-09执行记录：数据修补后151成员全池参与，2016-03-31至2026-05-15共2457个
交易日，完成2至20规模的57组精确评价，保留17、17、18、13、10个成员的五个候选。
此处数量是该次搜索的结果，不是模板。名单、分段指标、相关性和完整配方位于
`runs/factor_selection/20260908_datarepair_multipath/`；没有自动改动生产策略。

## 观察与组合验证

`OBSERVE_COMMON_HORIZON`保留共同H周期的126日IS＋42日OOS敏感性观察，合同明确标为
不可入库。滚动Walk-forward、locked OOS和截止日后的真实前向数据，只用于已经冻结的
具体策略；它们不会改变因子有效身份。

## 使用顺序

1. 新因子：填写`FACTOR_NAMES`，运行默认`VALIDATE_FACTOR_BATCH`。
2. 第一次建库或重建：显式选择`VALIDATE_ALL_INTRADAY`。
3. 审阅正式run后：选择`ADMIT_COMPLETED_RUN`。
4. 需要组合候选时：选择`SELECT_EFFECTIVE_SUBSETS`。
5. 审阅`portfolio_candidates`及全部规模评价，冻结待验证成员；
6. 在策略库中显式引用通过组合级验证的因子子集和完整策略YAML。

检验、入库、子集选择和策略修改必须分别运行；任何一步都不得隐式执行下一步。

## 历史口径复核（2026-09-06）

这一节只记录旧流程追溯结果，在新的全池正式运行前必须先解决统计口径差异。

- 旧6/27/47阶段已经检验H5/H10/H20；旧27个候选中best period约为H5=2、
  H10=5、H20=20。它们在旧生产组合中仍是每日共同截面排序和ICIR合成；
  best period是准入证据，不是自动持有期或必须分袖的路由字段。
- 2026-09-06的606因子run以横截面Fama-MacBeth斜率的`OLS-HAC p`执行层级
  Simes/BH和selection-adjusted local BH，得到37个统计发现。对其已落盘的全部结果
  只替换FDR输入做反事实复算：使用`IC-HAC p`时，注册多周期因子级BH为121个，
  固定H20因子级BH为134个。因此132→37的主因是FDR输入统计量，不是多周期本身。
- 旧全量396检验将因子分为4个独立run后取并集，每批各自做多重检验；
  当前606个是一个统一检验族。但按旧4批方式对当前`OLS-HAC p`复算仅得42个，
  所以分批只是次要差异，不能解释132。
- 旧表中的`t`与`IC`成对报告，而当前`best_t`明确是OLS-HAC t。旧的
  `runs/ia_full_b1..b4`未提交Git，手工备份与ZIP也没有这四个运行产物；
  `scripts/dedup_all.py`只将这些未保留JSON里的`best_period>0`视为已通过。
  因此旧FDR的原始p值无法逐字节证明；数量反演强烈指向IC-HAC，但不应伪装成已找回原始文件。
- 2026-07-23手工副本进一步确认旧`ICTest`的`t`来自逐日Pearson IC序列的
  Newey-West/HAC均值检验。该副本的正式全量脚本尚用全局Bonferroni：4058个假设、
  `alpha=0.05/4058`、`t>=4.371823`，后接`|IC|>=0.02`、`|IR_NW|>=0.50`和主方向
  命中率`>=52%`，1351因子最终为0；另一个人工分析用`t>=1.96`、`|IC|>=0.015`、
  `|IR_NW|>=0.10`得到109个，但它不是FDR正式准入。该证据确认统计量而非恢复了
  后来约132个FDR通过者的原始阈值。
- 原始MAD去极值+日截面zscore与当前intraday raw变体基本一致；未来收益也都是
  `close.shift(-H)/close-1`。这两项不是数量骤降的主因。
- 因子与收益的底层行情语义已变：旧分钟入口曾把同品种根的全部合约按分钟聚合，
  当前使用T-1因果主力合约、交易所交易日和连续合约调整；夜盘自然日归属也在旧全量
  运行后修正。这会改变单因子IC的绝对值甚至方向，但它是数据正确性差异，应与FDR统计口径分开。

本次恢复据上述证据采用`IC-HAC p`作为FDR输入；OLS-HAC斜率/t/p继续写入详细产物，
仅作诊断。旧四批原始p值未留存，因此这是证据最强的恢复口径，不宣称逐字节复原。

随后补充找回的历史会话执行记录进一步交叉印证了甜区漏斗，而不是把“越早”当成
“越正确”：2026-08-01的190因子记录为层级FDR `q=0.10`通过80个，随后
`|IC|>=0.01`、`|t|>=2.0`仍为80个，换手仅作诊断，相关性筛选才从80缩至14；
2026-08-04的396因子记录为132个通过FDR，再与6因子去重为64、候选间去重为27。
因此本项目的统计有效库应停在相关性去重之前；相关性与组合增益属于下游策略选择。
