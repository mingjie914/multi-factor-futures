# 周期一致性与多频率共存设计指南

> 撰写日期：2026-07-31  
> 基于 `multi_factor` 框架实战沉淀，适用于任何需要多频率（日频/分钟）因子共存
> 的策略框架的新建或重构。

---

## 一、核心原则

### 1.1 周期 = bar 计数，不是天数

框架中所有"周期"参数一律解释为 **bar 数**，而非日历天数。

```
频率=daily  → 1 bar = 1 交易日  → horizon=20 表示 20 个交易日
频率=1min   → 1 bar = 1 分钟    → horizon=20 表示 20 分钟
频率=5min   → 1 bar = 5 分钟    → horizon=20 表示 100 分钟
```

**严禁**在任何下游模块把 bar 数当作天数进行硬编码换算（如 `* 252 / 365`）。

### 1.2 年化统一通过 `bars_per_year`

所有需要"年化"的地方，使用唯一的 `bars_per_year` 参数：

```python
# 正确
annual_vol = daily_vol * np.sqrt(bars_per_year)
daily_cost = annual_cost / bars_per_year

# 错误 —— 严禁硬编码
annual_vol = daily_vol * np.sqrt(252)   # ← 只对日频正确
```

### 1.3 频率信息从入口注入，全流程透传

不要在子模块中猜测或推断频率。从 CLI/配置文件 → PipelineRunner → 所有下游模块，
频率参数必须显式传递。

因子输出/研究频率与原始输入读取频率是两个契约。当前`intraday.py`主要读取1min或
显式5min，但输出均为daily；已配置数据源按请求频率路由，30min由15min显式重采样。

## 二、频率抽象层设计

### 2.1 PeriodUnit 枚举

```python
class PeriodUnit(str, Enum):
    DAILY = "daily"        # 日度
    MINUTE_1 = "1min"
    MINUTE_5 = "5min"
    MINUTE_15 = "15min"
    MINUTE_30 = "30min"
    HOURLY = "hourly"
```

### 2.2 元数据表（按频率）

```python
_PERIOD_META = {
    PeriodUnit.DAILY:     {"bars_per_day": 1,   "bars_per_year": 252},
    PeriodUnit.MINUTE_1:  {"bars_per_day": 240, "bars_per_year": 240 * 252},
    PeriodUnit.MINUTE_5:  {"bars_per_day": 48,  "bars_per_year": 48 * 252},
    PeriodUnit.MINUTE_15: {"bars_per_day": 16,  "bars_per_year": 16 * 252},
    PeriodUnit.MINUTE_30: {"bars_per_day": 8,   "bars_per_year": 8 * 252},
    PeriodUnit.HOURLY:    {"bars_per_day": 4,   "bars_per_year": 4 * 252},
}
```

### 2.3 PeriodContext（不可变值对象）

```python
@dataclass(frozen=True)
class PeriodContext:
    unit: PeriodUnit
    bars_per_day: int
    bars_per_year: int

    @classmethod
    def from_string(cls, freq: str) -> "PeriodContext":
        # 支持别名
        aliases = {"1m": "1min", "5m": "5min", "daily_intraday": "daily", ...}
        normalised = aliases.get(freq.lower(), freq.lower())
        unit = PeriodUnit(normalised)
        return cls.from_unit(unit)
```

**关键设计决策**：
- 不可变（frozen dataclass），避免下游意外修改
- `from_string` 支持别名（如 `daily_intraday → daily`），让配置键可以比 PeriodUnit 更细分

### 2.4 频率别名：解决"配置键比枚举值更细"的问题

当需要同一频率下不同参数（如传统日频 vs 日内聚合日频），不要扩展 PeriodUnit 枚举，
而是用别名（alias）：

```python
aliases = {
    "daily_intraday": "daily",  # 归一化到 daily，但配置键保留 daily_intraday
}
```

配置文件中使用别名作为键：

```yaml
wf_train_bars_by_frequency:
  daily: 500              # 传统日频
  daily_intraday: 126     # 日内聚合日频（更短的窗口）
  1min: 6000
wf_max_folds_by_frequency:
  daily_intraday: 5       # 只保留最近约17个月的正式证据
```

代码中查找时，**先用原始键查找，失败再回退到归一化键**：

```python
def _minimum(mapping, original_key: str, canonical_key: str, label: str) -> int:
    values = dict(mapping or {})
    key = original_key if original_key in values else canonical_key
    return int(values[key])
```

**陷阱**：不要在查找前无条件归一化频率字符串，否则会丢失 `daily_intraday` 的独立配置。

## 三、全流程频率注入点

### 3.1 注入链

```
CLI --frequency daily
  → PipelineRunner(frequency="daily")
      → self.period_ctx = PeriodContext.from_string(frequency)
           ├─ _build_signal_layer    → sizer.periods_per_year
           ├─ _build_optimization_layer → cost_model.periods_per_year
           ├─ _build_testing_layer   → LayeredBacktest(periods_per_year=...)
           └─ workflows              → PeriodContext.from_string(frequency)
```

### 3.2 PipelineRunner 是最小注入点

```python
class PipelineRunner:
    def __init__(self, ..., frequency: str = "daily"):
        self.period_ctx = PeriodContext.from_string(frequency)
        # 下游模块通过 self.period_ctx 获取 bars_per_year
```

### 3.3 各模块改造清单

| 模块 | 原问题 | 改造方式 |
|------|--------|----------|
| `optimization/costs` | `periods_per_year=252.0` 默认值 | 从 runner 注入，已有参数只需传值 |
| `testing/layered` | `params.get("periods_per_year", 252.0)` | 已有覆盖机制，调用方传正确值即可 |
| `backtest/engine` | `training_window=750`（bar 计数，频率无关） | 不改 — bar 计数本身已频率无关 |
| `workflows/research` | `factor_start = ic_start - 365 days` | 改为从 `warmup_days_by_frequency` 配置读取 |
| `workflows/walkforward` | 折叠段硬编码年度日期 | 改为 `_build_rolling_folds(calendar, train_bars, test_bars, step_bars)` |

### 3.4 不需要改的（保持克制）

| 模块 | 原因 |
|------|------|
| `backtest/engine` `Timedelta(days=...)` | 尾端安全 buffer，多读不造成功能错误 |
| GP 因子挖掘的窗口采样 | 挖掘插件独立，不阻塞主流程 |
| 因子内部 `rolling(20)` | 属于因子逻辑语义，不属框架层 |
| SPEC 因子窗口 | 已通过 `spec_factor.py` 参数化 |

## 四、收益率与年化计算

### 4.1 单期收益率

```python
# 持有期 forward return（bar 数语义）
forward_return = close.pct_change(period).shift(-period)

# period=5 在日频 = 5天前瞻收益
# period=5 在1min = 5分钟前瞻收益
```

### 4.2 年化波动率

```python
annual_vol = daily_return.std() * np.sqrt(period_ctx.bars_per_year)
```

### 4.3 年化收益率

```python
# 非重叠调仓频率
ann_factor = bars_per_year / holding_period  # holding_period 也是 bar 数
annual_return = period_return.mean() * ann_factor
```

### 4.4 成本分摊

```python
# 交易发生的 bar：完整成交名义 × 单位成本率
trade_cost = executed_traded_notional * turnover_cost_rate

# 持有期保守预算：按总暴露逐 bar 摊销
holding_cost = gross_exposure * annual_roll_cost / bars_per_year

# 1分钟研究若启用持有预算，bars_per_year 必须使用分钟 bar 年化数
```

### 4.5 夏普比率

```python
# 统一公式（频率无关）
sharpe = (annual_return - risk_free_rate) / annual_vol
```

## 五、Walk-forward 折叠段生成

### 5.1 核心函数

```python
def _build_rolling_folds(
    calendar: pd.DatetimeIndex,
    train_bars: int,    # 训练窗口 bar 数
    test_bars: int,     # 测试窗口 bar 数
    step_bars: int,     # 滑动步长 bar 数
) -> list[tuple]:
    """
    返回 [(name, train_start, train_end, test_start, test_end), ...]
    
    关键约束：
    - 每个 fold 的 test_start = train_end + 1（无前瞻泄露）
    - 测试集之间非重叠（step >= test 时保证）
    - 尾部不足一个完整 fold 时安全截断
    """
    folds = []
    cursor = 0
    min_len = train_bars + test_bars
    while cursor + min_len <= len(calendar):
        train_end_idx = cursor + train_bars - 1
        test_start_idx = train_end_idx + 1
        test_end_idx = test_start_idx + test_bars - 1
        if test_end_idx >= len(calendar):
            break
        folds.append((
            f"折{len(folds)+1}",
            calendar[cursor].date().isoformat(),
            calendar[train_end_idx].date().isoformat(),
            calendar[test_start_idx].date().isoformat(),
            calendar[test_end_idx].date().isoformat(),
        ))
        cursor += step_bars
    
    # 回退：fold 数不足时缩短 step
    if len(folds) < 3 and step_bars > test_bars // 2:
        return _build_rolling_folds(calendar, train_bars, test_bars, test_bars // 2)
    return folds
```

### 5.2 参数选择指南

| 数据量 | 建议 train | 建议 test | 建议 step | 预期折数 |
|--------|-----------|----------|----------|----------|
| ~350 天（17个月） | 126（半年） | 42（2个月） | 42 | 5 |
| ~2000 天（8年） | 500（2年） | 125（半年） | 125 | 12 |
| ~5000 根 bar（1min） | 6000（~1个月） | 2000（~2周） | 2000 | ~2 |

**原则**：test ≥ 20 个截面才有统计意义。折数 ≥ 4 才有交叉验证意义。
日内因子默认检验按主配置只取截止日前紧邻的126交易日IS和42交易日OOS，并另取90日历日
预热；更早历史不参与本次因子、方法或参数选择。全历史仅在用户明确要求时用于隔离研究。

## 六、常见陷阱与解决方案

### 6.1 `np.sqrt(252)` 硬编码

**症状**：分钟频率下风险预算完全错误。

**修复**：统一用 `periods_per_year` 参数，在入口处从 `PeriodContext` 注入。

```python
# 错误
target_risk = account_value * vol_target / np.sqrt(252)

# 正确
target_risk = account_value * vol_target / np.sqrt(self.periods_per_year)
```

### 6.2 归一化丢失配置键

**症状**：`daily_intraday` → `normalise_frequency` → `daily`，后续查找配置用 `daily` 键，
丢失了 `daily_intraday` 的独立参数。

**修复**：保存原始键，查找时先用原始键：

```python
original_freq = frequency
frequency = normalise_frequency(frequency)
value = config_dict.get(original_freq) or config_dict[frequency]
```

### 6.3 `list` 无 `.min()` 方法

**症状**：某个因子用 `list` 传日期，但下游调用 `dates.min()` 报错。

**修复**：在入口处统一转换：

```python
dates = pd.DatetimeIndex(dates)
```

### 6.4 隐式返回 `None`

**症状**：函数多条路径，某条路径忘记 `return`，隐式返回 `None`，下游 `if "close" in panel` 崩溃。

**修复**：所有分支末尾显式 `return {}`。

### 6.5 前缀碰撞

**症状**：`A` 匹配了 `AG2501`（因为 `"AG2501".startswith("A")`）。

**修复**：先解析完整字母根，再按规范根精确匹配；长度排序仍会把未知或畸形代码
错误归类，因此禁止作为行情筛选规则：

```python
parts = contract_symbol_parts(symbols)
rows = rows.loc[parts["root"].isin(canonical_roots)]
```

### 6.6 大小写不匹配

**症状**：Parquet 数据中 `rb2505`（小写），universe 中 `RB`（大写），规范根无法直接比较。

**修复**：先统一大小写并规范化具体合约，再精确比较完整根或完整合约：

```python
canonical = canonicalize_contract_aliases(frame)
```

### 6.7 预热期不足

**症状**：`factor_start = ic_start - 365 days`，对 1min 频率的大量数据是浪费，对日频也不够灵活。

**修复**：在配置中按频率分别设定：

```yaml
warmup_days_by_frequency:
  daily: 252
  daily_intraday: 90
  1min: 60
```

### 6.8 日历天数硬编码

**症状**：`pd.DateOffset(years=1)` 硬编码。

**修复**：
```python
warmup_days = config.warmup_days_by_frequency.get(frequency, 252)
factor_start = ic_start - pd.Timedelta(days=warmup_days)
```

## 七、多周期策略共存

### 7.1 问题描述

以下是多周期组合需要遵守的运行边界。当前 `RUN_AND_COMPARE` 默认生产账本仍是
统一日度 T+1 账本；显式 `RUN_AND_COMPARE_CONFIGURED` 已可按 YAML 的
`sub_portfolios` 实际运行 H5/H10/H20 sleeve，但它同时加载各 YAML 的模型、风险、
rebalance 与 meta-optimizer，属于完整配置挑战，不是只改变周期的实验。一个完整策略
可能需要：
- 日内持仓（1min/5min 信号，分钟级调仓）
- 日频持仓（daily 信号，日频调仓）

两者的信号频率、调仓频率、成本频率都不同，但最终要汇总到同一 NAV。

### 7.2 解决方案：统一到日频 NAV

**核心思想**：所有子策略的收益按日频汇总，分钟级策略在日内产生信号后，
按日频计算当日收益。

```
1min 信号 → 每分钟产生目标权重 → 每分钟收益 → 日频汇总
daily 信号 → 每天产生目标权重 → 每天收益
                 ↓
          日频 NAV（每日一条记录）
```

### 7.3 配置示例

```yaml
sub_portfolios:
  - name: intraday_1min
    factors: [jump_intensity_20d, price_peak_count_20d]
    frequency: "1min"           # 信号频率
    rebalance_freq: "30min"     # 调仓频率
    training_window: 6000       # bar 计数
    capital_weight: 0.3

  - name: daily_trend
    factors: [momentum_20d, trend_strength_20d]
    frequency: "daily"
    rebalance_freq: "weekly"
    training_window: 500
    capital_weight: 0.7
```

### 7.4 关键实现细节

1. **成本独立计算**：分钟级策略用分钟级的 `bars_per_year`，日频用日频的
2. **NAV 以日频为基准**：两个策略的日收益相加得到组合日收益
3. **调仓时机**：分钟级策略的调仓必须在日频决策之前完成
4. **数据对齐**：分钟级因子产生的信号需要和日频因子在同一时间轴对齐

## 八、最小化修改检查清单

当需要为一个现有框架新增频率支持时，按以下顺序排查：

- [ ] 是否存在 `np.sqrt(252)` 或 `periods_per_year=252` 硬编码？
- [ ] 是否存在 `pd.DateOffset(years=1)` 或 `Timedelta(days=365)` 硬编码？
- [ ] 是否存在 `pd.bdate_range` 但未考虑分钟频率？
- [ ] 配置查找是否无条件归一化频率字符串（丢失 `daily_intraday`）？
- [ ] 日期传递是否全部使用 `DatetimeIndex`（而不是 `list`）？
- [ ] 符号匹配是否处理了大小写和前缀碰撞？
- [ ] 函数是否有隐式 `return None` 的分支？
- [ ] WF 折叠段是否硬编码了具体日期？
- [ ] 预热期是否可配置？
- [ ] 最小 bar 数门槛是否按频率分别设置？

## 九、总结

| 原则 | 说明 |
|------|------|
| 周期 = bar 计数 | 不在任何地方将 bar 数换算为天数 |
| 年化 = bars_per_year | 唯一的年化因子，按频率查表 |
| 频率从入口注入 | 不推断、不猜测、不默认 |
| 配置键可比枚举更细 | 用别名机制，不扩展核心枚举 |
| 查找先用原始键 | 保留 `daily_intraday` 语义，不行再回退 |
| 折叠段用 bar 生成 | 不写死年份日期 |
| 改动最小化 | 优先改配置，其次改注入点，不改引擎核心 |
