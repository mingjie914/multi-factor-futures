# Rust 改造可行性评估报告 (2026-08-06)

| 阶段 | 耗时 | 占比 | 性质 |
|------|------|------|------|
| **冷启动 compute (6因子)** | 118.6s | 55% | 1min parquet 6400万行 IO + 字符串处理 (物理上限) |
| **IC_IR 回测 (全段 597天)** | 105.5s | 45% | 见下方细分 |
| ├ erc_w (HARP 协方差求解) | ~30s | 14% | scipy 优化 (100次 5.3s) |

**同进程热缓存**: compute 归零 (0s), 回测 105s 不变 (回测本身无缓存可复用).

## 二、Rust 改造 ROI 评估

| 模块 | 当前耗时 | Rust 预期 | 难度 | 稳定性 | 收益判定 |
|------|---------|----------|------|--------|---------|
| **HARP 风险平价优化器** | 30s/回测 | 5-20× | 中 | 高 (纯数学, 逻辑稳定) | ✅ **最佳候选** |
| **LW 协方差 + inv** | 30s/回测 | 10-50× | 中 | 高 (numpy 标准运算) | ✅ 候选 |
| **IC_IR 批量计算** | 35s/回测 | 10-50× | 中高 | 中 (依赖 pandas 结构) | ⚠️ 需先剥离 pandas |

## 三、关键判断

### 1. Rust 收益上限有限
- **冷启动 118s 的瓶颈是 parquet IO (6400 万行读取 + 字符串解码)**, 不是计算.
  Rust 用 arrow-rs 读 parquet 可省 pandas 层, 预计 **118s → 30-40s** (3-4×), 非 10×+.
- **回测 105s 的瓶颈是 HARP/LW/IC 的 numpy/scipy**, 已接近 C 性能. Rust 重构可再快 2-5× (省 numpy 调用开销), 但 105s → 30-50s.

### 2. 真正的 Rust 价值点: HARP + LW 协方差
- 这两个模块**纯数学、逻辑稳定、输入输出简单** (矩阵 in → 权重 out), 最适合 Rust.
- 用 PyO3 封装, Python 侧接口不变, 最小侵入.
- 预期: 回测 105s → 70-80s (省 ~30s HARP + ~30s LW 中一部分).

### 3. GPU 替代方案 (本机 RTX 4080 SUPER 16GB)
- HARP/LW/IC 全是**矩阵运算**, CuPy 可 6-100× 加速.
- 但**数据在 CPU 内存 (pandas), 需频繁 H2D/D2H 传输**, 单次回测数据量小 (38×597), 传输开销可能吃掉收益.
- **结论: 小矩阵 (38×597) GPU 收益有限; 大矩阵 (因子×因子) 才值得 GPU**.

### 4. 综合建议
| 方案 | 改动 | 预期 | 风险 | 建议 |
|------|------|------|------|------|
| **Rust 重构 HARP** | PyO3 ~200行 | 回测 -30% | 中 (接口适配) | ⭐ 若追求极致可做 |
| **numpy 向量化 LW** | ~50行 | 回测 -15% | 低 | ✅ 先做这个 (零风险) |
| **cached LW 协方差** | ~20行 | 回测 -20% | 低 | ✅ 最优先 (LW 协方差可缓存复用) |
| Rust 重构因子引擎 | 大 | 冷启动 3-4× | 高 | ❌ 性价比低 (IO 瓶颈) |
| GPU (CuPy) | 中 | 不确定 | 中 | ⚠️ 小矩阵收益有限 |

## 四、最终结论

**Rust 改造技术上可行, 但 ROI 中等**:
- ✅ 值得: HARP 优化器 + LW 协方差 (纯数学, 逻辑稳定, PyO3 封装)
- ❌ 不值得: 因子计算引擎 (IO 瓶颈), 回测事件循环 (状态复杂)
- 冷启动 118s 的 IO 瓶颈 Rust 只能 3-4×, 不如先做**5min 预聚合** (预期 10-20×)

**最小修改优先顺序** (不动算法, 纯性能):
1. ✅ 已做: 列裁剪 + _RAW_CACHE + _expiry_ym 缓存 (同进程归零)
2. ⭐ 待做: **cached LW 协方差** (同 (t, 因子集) 的协方差复用, 回测 -20%)
3. ⭐ 待做: **5min 预聚合数据层** (冷启动 118s → 10s)
4. ⭐ 可选: Rust/PyO3 重构 HARP (回测 -30%, 需接口工程)

> 结论: 当前**不建议立即引入 Rust** (收益 30% 需 PyO3 接口成本). 优先做 numpy 缓存 + 5min 预聚合 (纯 Python, 低风险, 收益 40%+). 若未来因子池扩到 100+ 且回测成为日常高频操作, 再考虑 Rust HARP.
