# 多因子期货框架研究手册

## 1. 目标与边界

框架服务于期货因子发现、正式统计验证、组合研究和收盘决策。研究层可以探索，收盘目标权重
发布层必须失败关闭。当前10f仅是固定观察定义；其旧绩效已失效，不等于有效池最优或
生产批准；`config/default.yaml`保存10f固定观察基线，`config/target_publication.yaml`
没有获批部署包并保持关闭；关闭状态为 `NO_TARGETS`。

本框架不连接交易所、不发送订单、不接收成交回报；“目标权重发布配置”“发布批准”只表示是否允许
生成或发布收盘后的目标权重，实际委托与成交由外部系统或人工执行。

模块分为四层：

1. 发现层：人工因子、SPEC 枚举和 `factor_mining` 的 GP 搜索。
2. 验证层：点时数据、IC/HAC、分层、稳定性、多重检验和冻结 OOS。
3. 组合层：相关去重、家族约束、训练期权重、成本、容量和风险限制。
4. 决策层：只读取人工批准部署包；缺失或发布门关闭时输出 `NO_TARGETS`。

研究报告、SQLite 候选、旧回测优胜者和 JSON 快照都不是目标权重发布批准，也不会触发外部下单。

## 2. 数据与频率

本地分区Parquet是权威发布与恢复层；主框架可从Parquet或认证DuckDB镜像读取。
独立`factor_mining`目前仍通过`LocalParquetData`读取Parquet。MySQL、DolphinDB和AkShare
不属于当前框架的运行时依赖；历史文档若提及它们，仅表示旧适配器或外部资料来源。
原始输入与因子输出频率必须分开：当前`intraday.py`主要读取1min或显式5min数据，
但当前588个类均输出daily，注册horizon因此按交易日解释。真正分钟输出因子的horizon才按
分钟bar解释。

周期参数一律按所选频率的 bar 数解释：`frequency=1min, period=15` 表示 15 分钟；
`frequency=daily, period=5` 才表示约 5 个交易日。不同目标周期应在搜索前声明为不同
run，不能看完结果再挑最优周期而不计入多重检验。

分钟特征可在日内频率直接研究，也可聚合为低频决策信号。“高频挖、低频用”是可选
方式，不是强制日频。任何聚合都要保留交易日、夜盘和决策滞后的明确语义。

## 3. 因子发现

### 3.1 特征

首版挖掘引擎使用本地面板中真实存在的：

- OHLC、成交量、成交额、持仓量及变化；
- 1 bar 与多 bar 收益、lag、量额仓变化；
- MA、EMA、Bollinger、RSI、ATR、MACD；
- 实现波动率、上下半方差、偏度、峰度；
- 量价相关、成交集中度和 Amihud 流动性代理；
- 可选的本地期限结构聚合字段。

结算价、库存、仓单、现货基差、会员持仓、宏观和另类数据只有在本地数据源能提供可靠
point-in-time 面板后才能加入。不能用同日最终值、未来修订值或伪造代理填补。

### 3.2 GP 算子

搜索空间包含保护加减乘除、max/min/avg、平方/立方、有符号开方和对数、delay、
delta、滚动均值/EMA/标准差/极值、相关与协方差、时序和横截面 rank/zscore/demean。
条件逻辑和慢速 Python rolling callback 默认关闭，只有预先声明并有性能预算时启用。

每个表达式受最大深度、复杂度惩罚、内容哈希去重和信号相关去重约束；换手仅作诊断，
不参与 GP fitness、费用或因子准入。
保护算子必须保留缺失值语义，不能把未知数据当 0。

### 3.3 黑箱与 GPU

首版只挂载符号表达式；候选契约已经预留模型类型，但桥接器会拒绝黑箱模型。后续只有
在特征、验证和候选治理稳定后，才接入 XGBoost、神经网络或 Agent。当前剖析显示瓶颈
在 CPU/内存带宽和滚动统计，GPU 搬运成本不划算；黑箱批量训练再单独评估 GPU。

## 4. 候选仓库与主框架

SQLite、JSON 快照和 `Factor` 各自负责不同事情，可以共存：

- SQLite：可变的候选、运行参数、状态和血缘目录；不参与主框架运行时计算。
- JSON 快照：带 SHA-256 的不可变交付集合。
- `Factor`：主框架统一计算接口和 registry 对象。
- SPEC：适合 `base + transform` 的可枚举公式；一般 GP 树不强塞进 SPEC。

`main.py <workflow> --mined-snapshot PATH` 会先验证快照，再由
`factors/user/auto_mined_bridge.py` 动态创建普通 `Factor` 子类。未传快照时桥接器为空，
不改变现有行为。详细命令见 `factor_mining/FRAMEWORK_INTEGRATION.md`。

## 5. 验证顺序

因子构思、编码、合成数据和单元测试可快速迭代。开始查看真实历史 IC、HAC t 值、收益
或最优周期前，必须冻结研究协议：

```text
公式/频率/目标/日期/假设数预声明
  -> 点时因子和前瞻收益
  -> 未收缩单因子 OLS/Fama-MacBeth + HAC p 值
  -> 预声明的多重检验
  -> |IC|、方向命中率、分层、换手诊断、成本和分段稳定性
  -> 相关去重和经济家族上限
  -> 训练期 Ridge 或其他组合估计器
  -> 成本、容量、风险约束
  -> 冻结 walk-forward / 一次性 locked OOS
  -> 人工部署批准
```

Ridge 不提供筛选 p 值。搜索期 IC/IR 和收益只是适应度。当前期货横截面较窄且前瞻收益
可能重叠，不能机械套用股票月频 `IR > 0.5`；当前正式流程使用层级 FDR `q=0.10`、
`|IC| >= 0.01`、`|HAC t| >= 2`、预声明方向、分段稳定性和完整协议共同判断。

“只把 12 个公式交给 Bonferroni”不是当前硬编码限制，但所有实际送检假设都必须按冻结
协议完整计数。探索规模很大时，可预声明分阶段 FDR/家族筛选与独立确认，不能在看结果
后临时缩小分母。

## 6. 因子池阶段

运行时 registry 是发现池，不等于因子库。持久阶段为：

1. `mined_candidate` / `discovery_pool`：仅发现。
2. `development_candidate` / `historical_screened_pool`：通过历史审计，仍非独立 OOS。
3. `oos_validated_pool`：通过未消费区间的冻结验证。
4. `portfolio_eligible_pool`：通过相关、成本、容量和风险审核。
5. `deployment_approved_pool`：人工批准目标权重发布包；外部执行系统或人工下单另行审批。

其中 `production_approved` 仅表示目标权重部署包的治理状态，不表示本框架已连接实盘或自动下单。

状态只能凭审计证据晋级，不会自动写 `config/default.yaml` 或 `config/target_publication.yaml`。

## 7. 风险与历史证据

组合层使用波动率/ATR 风险预算，并施加单品种、板块、总敞口、净敞口及配置层面的
调仓限制。成交成本按每次完整成交名义金额的 0.02% 计提；筛选成功后的研究回测另按
持仓暴露摊销年化 0.105% 的移仓成本。

当前没有数据更新后可引用的正式结果bundle，状态仍为`NO_TARGETS`。更新前的H20运行
只作为同区间重放对照；append-only holdout ledger继续记录已消费样本事实，不能被解释
为阶段日期配置。固定窗口与重检顺序以`docs/因子检验与准入流程.md`的handoff为准。

## 8. 日常命令

```powershell
$PY = 'E:\Python\Pythonvenv\Scripts\python.exe'

& $PY -X utf8 -B main.py data-health --config config/default.yaml --strict
& $PY -X utf8 -B main.py mining dev-smoke --periods 600 --symbols 12
& $PY -X utf8 -B main.py research --help
& $PY -X utf8 -B main.py adaptivity --help
& $PY -X utf8 -B main.py walkforward --help
& $PY -X utf8 -B main.py summarize --help
& $PY -X utf8 -B main.py close --as-of YYYY-MM-DD --output runs/close_check.json
& $PY -B -m pytest -q -p no:cacheprovider
```

`close` 只执行收盘后目标权重发布门；关闭时输出 `NO_TARGETS`，不产生订单。
回测仅在显式提供 `--target-output <路径>` 时导出目标权重文件；它不是订单或成交回报。

研究证据保留规则见 `runs/README.md`，维护和版本控制见 `MAINTENANCE.md`。
