## 拓扑与唯一职责

```text
全部因子 → 冻结准入检验 → 有效库 → 组合构建/选择 → 目标权重
                                                   ↓
                 成本模型 → 原生回测账本：漂移/交易可行性/具体合约转换
                                                   ↓
                                  执行换手 → 扣费 → 净收益/净值
                                                   ↓
                     通用成本诊断 + 分段稳健性 → 报告/备选资格讨论
                                                   ↓ 显式请求
                                   成交校准/容量/执行仿真
```

- `optimization/costs.py`：现有成本模型负责收费规则；`evaluate_cost_sensitivity`
  是通用回测后诊断入口。复用现有模块，不新增策略专用脚本或第二套注册机制。
- `backtest/research_ledger.py`：实际生效权重、合约转换、归一化换手、费用及净值
  的逐日账本；`backtest/engine.py`共用转换与收益核算函数。统计不得另推一套成交。
- `backtest/metrics.py::compute_turnover_metrics`：只接收已执行持有区间的完整换手。
  调仓决策、目标权重差、信号排名变化不可冒充执行统计。
- 正常回测保存及生产配方入口默认输出`cost_diagnostics.json`；归因报告调用同一函数，
  按全期/截止前/观察段展示。输入为账本，不依赖策略名称、因子数或有效库身份。

  持有费处理与样本数量。其他收费模型沿用现有`costs.type`注册入口显式选择，
  不自动择优、更不按模拟实盘段表现切换模型。尚未实现的执行仿真不得声称可选可用。

## 基础核算定义

1. 目标权重W[T]用于T+1持有区间；当前是收盘到收盘的研究近似，不是临收盘订单
   的真实成交仿真。交易可行性和延期换月按现有数据门禁处理。
2. 基准是归一化净值，不要求人民币本金，不模拟保证金、整手、追加保证金或券商现金账。
   毛收益为生效权重乘资产收益之和，净收益＝毛收益－交易费－持有费。
3. 调仓前权重按价格和净收益漂移；完整换手＝具体合约目标权重与漂移权重绝对差之和。
   买卖、开平均累计，不除2。总敞口2已在权重中，不能再额外乘2。
4. 初始空仓建2倍敞口：换手2；平旧2再开新2：换手4。反向翻仓计平旧加开新。
   全期第一个净值点只是锚点，无前置持有收益；最后收盘目标不视为已执行，
   不默认强制清仓或收取尚未发生的退出费。强制期末清仓必须是显式情景。
5. `executed_traded_notional`与`turnover`均为归一化完整换手，不是金额；
   `half_turnover=0.5*turnover`只作兼容字段。年化＝252×全部持有日均值，含零成交日。
   `avg_turnover`保留历史的有成交日均值；`avg_daily_turnover`才用于年化，不能混用。
6. `executed_roll_turnover`是变更合约仓位的全部平开腿，包含同时发生的加减仓/反向。
   它属于完整换手子集，不能再加到总换手上收费，也不应称为固定数量的纯移仓增量。
   “纯维持方向的移仓量”若另做诊断可定义为同号仓位的2×min(旧绝对仓位,新绝对仓位)，
   但本次不改变已有换月字段定义和数值。
7. 截止后第一天的收益、费用、执行换手全部属于观察段；前一收盘只作净值锚点。
   历史分段不重置仓位、不重新收初始建仓费、不漏掉边界一天。
8. 费用字段是当日归一化收益扣减；简单求和不是复利净值损失或人民币费用。
   利润贡献使用前日净值链式加权，逐品种毛贡献加独立负费用须与区间净收益对账。
   历史`total_transaction_cost`字段有包含持有费的兼容含义，不能解释为纯手续费；
   明细对账使用`trade_cost`和`holding_cost`，不将摘要字段再次扣费。

## 成本后的收益与稳健性评价

- 已实现：固定原账本路径，替换交易费率而非叠加一份新费用；持有费用保持原值。
  输出完整年换手、净年化/夏普/回撤、各情景和按复利收益为零求得的盈亏平衡费率。
  零交易、零交易费仍亏损、情景净值耗尽分别标识，不给虚假无穷承受力或通过结论。
- 接着对关键情景重放同一目标权重的原生账本，让扣费后的漂移重新计算；费用上升
  不得在固定路径测试中提高净值，重放与静态测试则不要求逐点相等。
- 沿冻结时间分段/年度/滚动252日比较净年化、夏普、最大回撤及修复时长、正收益比例、
  最差阶段和品种/板块贡献集中度。长历史诊断与准入短区间分开；2026-05-15之后
  已被查看的观察段不作为新锁箱，不据此反复更换成员或费用模型。
- 深层检验需显式资金规模、合约乘数、每手费及开平差异、执行时间窗口、价差与
  成交量：计算参与率、整手与容量、延期/未成交、保证金约束；缺数据就标未验证。
- 不设未经批准的新硬门。候选应在现实成本加预先声明的安全余量后仍有收益，
  且不是靠少数时段/板块支撑；回撤及承受成本须符合事先风险预算。
  单看2倍费用夏普为正，不能自动批准实盘。

### 固定算法与唯一配置解析

沿用`select_long_short_pools`已验证语义：先按资格和cap形成每侧N+B的保留集合
（受实际容量限制），优先同向实际旧持仓，再按分数补足N，输出仍按原排名排序。
0或明确空仓沿原选池；并列分数保留原稳定排序；两侧不重叠。缓冲导致约束不可行
时，沿已有B0回退并记录原因，不能借缓冲放松约束。不可交易旧仓由账本处理，
不以目标已剔除为由虚构平仓。保留优先可能推迟强新品种进入，不承诺所有策略增益。

- `rank_exit_buffer`只接受非负整数，拒绝布尔值、小数和负数。0即关闭，不另加enabled。
- 全局唯一默认在`production_portfolio`。策略目录仅增加同名可空的窄覆盖字段：
  未声明继承默认，显式0关闭；不开放任意配置覆盖字典，不复制完整YAML。
- 沿现有配置校验入口一次解析为完整配方。显式实验参数是研究run覆盖并写合同，
  不回写策略目录；若与已解析配置不一致，应报错而非选择一个隐含优先级。
- 原生比较仍校验策略YAML与全局基础配方一致，然后只应用目录显式排名缓冲覆盖。
  当前已批准不同策略采用不同B值，因此完整策略比较允许这一项差异，并在图例、
  报告与运行合同标明；不能再声称仅有因子成员不同。其他配方差异仍拒绝。
  不得借`RUN_AND_COMPARE_CONFIGURED`切到另一套模型/风险/账本后，把差异全归因于缓冲。
- 当前10组显式设置缓冲（含0）；因子集的`selection_context`仅存证据，不放执行开关。

### 共享实现与使用

策略目录条目的`rank_exit_buffer: null`或省略表示继承，显式0表示关闭。
单策略和多策略原生运行均使用已解析的窄覆盖；多策略基础配方仍相同，
仅目录显式缓冲允许不同。研究实验不自行回写目录，本次采纳基于用户单独授权。
`PortfolioEvaluator.run(factors, recipe)`是共用执行入口，返回实际决策目标、
生效持仓、账本及诊断；正值调用无实际状态的`weights()`会报错。
`CombinedStrategy.signal(date, actual_holdings=..., holdings_date=...)`正值时必须提供
同一决策日收盘后的真实状态，显式空仓可以，缺失状态不可以。
最后一天也记录决策目标，但没有下一持有日，故不会虚构成交或扣费。

| 现有位置 | 必要调整 |
|---|---|
| `core/config.py`、`config/default.yaml` | 增加默认0及窄策略覆盖的校验；未知/不支持路由显式拒绝 |
| `optimization/portfolio_construction.py` | 复用现有选池函数，不新建策略专用算法；内部exit_buffer与规范配置字段在单一边界映射 |
| `research/historical_portfolio_search.py` | 现有配方记录参数及缓存身份；将实验的实际持仓决策连接移入共享评估调用，默认0沿原分支 |
| `run_portfolio_workflow.py`、`workflows/factor_selection.py`及现有实验入口 | 共用已解析配方与原生账本；移除重复连接代码，不新增另一套成本/回测实现；默认搜索网格不新增缓冲维度 |
| `strategies/combined.py` | 正值时显式接收有日期依据的实际收盘持仓，空仓须明确声明；未提供状态不能默认为空仓；0维持原接口行为 |
| 现有账本/报告产物 | 准确保存实际决策目标、生效权重和缓冲诊断；不重复扣费；合同/缓存区分成员、方向、B值、数据、样本及起始状态 |

如现有类型/函数已能承载所需信息，优先复用，不预建Manager、策略注册器、状态服务
或新配置文件。因子面板/信号/风险输入可共享，带状态的完整权重路径不可跨B值复用；
日期必须顺序推进，各策略状态隔离。不开启新一轮参数笛卡尔积，不改变因子公式
以冒充工程优化。性能改进面向共享计算路径，禁止按策略名称、固定成员或某个run
分支特例加速；默认0直接沿原路径，避免无用回调、状态复制或中间表转换。

先以实测耗时/CPU/内存定位热点：公共面板对齐、筛选、连接及聚合优先使用Polars，
减少循环内Pandas/Polars/NumPy互转，复用与成员/B值无关的只读输入。确有重复数值
或逐日循环热点时，在现有Rust内核边界复用或最小扩展通用算子，以批量调用摊薄
跨语言开销；不为38品种单次排序另建加速层。带状态决策保持时间顺序，不以并行化
破坏真实持仓依赖。使用Polars/Rust前后必须保持排序并列、空值、浮点、约束及费用
语义；记录实际调用后端及回退，不能以安装了Rust或仅导入库作为加速已生效的证据。
