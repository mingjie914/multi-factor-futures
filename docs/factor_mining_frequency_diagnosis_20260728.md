# 分钟因子频率与挖掘目标复核（2026-07-28）

## 结论

“使用 1 分钟数据挖掘、却先聚合为日频截面 IC 检验”不符合当前代码事实，不能作为零通过
的核心归因。本轮 P0 产物明确记录 `frequency=1min`、`periods_override=H`；数据管理器按
每个合约自身有效 bar 计算 `close.shift(-H)/close-1`，研究统计在每个分钟时间戳做截面
IC 和单因子 OLS/HAC，没有 `normalize()` 或日频 resample。

真正跨到日频/年频的步骤是：分钟换手按交易日聚合、自然年 regime 稳健性和组合治理。
这些是部署纪律，不会把正式 IC 标签改成日收益。

但本轮对齐检查发现了另一个真实口径差异：挖掘预筛使用声明的静态 47 品种
全集，正式 P0 使用滞后流动性动态池。一次包含 2024-03 特征预热段的静态
smoke 得到约 7.39 万个可估分钟截面，原正式 P0 在 2024Q2–Q4 动态池下有
1.91 万个。由于前者还多包含一个月的预热时间，这两个数字只能证明现有诊断不可
直接比较，不能把差值全部归因于动态池。

因此新预筛产物必须标注 `static_declared_universe`，不得把静态曲线冒充成正式
动态池证据。下一轮 campaign 应在完全相同的统计起止日与 point-in-time 品种池
下重算曲线；这是 universe/样本边界对齐问题，不是日/分钟频率问题。

## 本次修复

1. 新增真正的 forward-IC 衰减曲线：H=1/3/5/10/20/40，单位始终是候选的决策 bar。
2. 新增横截面信号排名持久性曲线，以及首次低于 0.5 的信号半衰期；与旧的“IC 序列
   自相关”明确区分。
3. 挖掘目标标签与正式框架统一为“每个合约自己的有效 bar”，修复公共索引局部缺失时的
   horizon 漂移风险。
4. GP fitness 加入成本调整后的 rank-weight 组合收益，并由 `economic_fitness_weight`
   冻结其权重。
5. 调仓频率从预测 horizon 中拆出，`rebalance_every_bars` 写入 run metadata 和候选哈希；
   CLI 默认 0 表示使用目标 horizon。
6. 衰减诊断按 8192 行分块，信号排名只复用一次，避免多年分钟面板为每个 horizon 重复
   生成全尺寸中间矩阵。

## 模型路线评估

- IPCA/Conditional Autoencoder 适合从“品种收益 × 特征”面板提取条件潜在因子，更适合作为
  日级或较低频的独立模型候选后端，不用于修复一个并不存在的日频 IC 错配。
- Random Forest/XGBoost 可作为非线性合成后端；输出必须成为带训练窗口、特征清单和模型
  哈希的 `kind=model` 候选，不能把同样本特征重要度当作因子证据。
- LLM 适合生成带经济家族、方向和 horizon 先验的表达式种子；论文中的“40 个因子”是
  外部研究结果，不等于在本地数据、成本和治理规则下已复现 40 个有效因子。
- 因子动量属于已有因子收益之上的动态配置层。当前没有足够大的已验证因子库，暂不应
  混入原始因子发现，以免把组合择时和因子有效性混为一项假设。

## 品种池

首轮 1 分钟 campaign 使用 47 个成熟品种；扩展训练 campaign 已覆盖 77 个可识别根品种，
数量并不低于“74 个”这一外部研究样本。正式 P0 仍使用 47 个，是动态流动性、历史长度和
数据质量约束的结果。下一步应报告每个时间点的有效截面宽度、剔除原因和板块覆盖，再决定
是否扩池；不能为了达到一个固定数字把低流动性或短历史品种机械加入。

## 下一轮冻结要求

- 新 campaign 必须使用新的 run ID；旧 P0/OOS 结果不能反向决定公式。
- 每个家族预声明目标 horizon 与调仓 schedule。
- 搜索同时报告原始 IC、成本调整得分、换手、IC 衰减和信号半衰期。
- 搜索与正式 P0 必须冻结同一份 point-in-time 品种池口径；未对齐前，
  `static_declared_universe` 诊断只作搜索导航。
- 若补入期限结构、会员持仓或仓单数据，必须保存 point-in-time 可用时间和数据快照哈希。
- q 继续维持 0.10；零产出时扩数据/家族/历史，过量时收紧到 0.05。
